# Rétrospective — construction du framework AI-DRIVEN-SDLC

## 1. Contexte

Construction du **framework SDLC piloté par agents IA** (v0.1.0), de 2026-10-11 à 2026-10-27.
Périmètre : socle et configuration, gabarits documentaires, CI et déploiement, adaptateurs
(Claude/Codex/OpenCode), 18 skills, tableau de bord `suivi-projet`, plugin OpenCode
`ai-sdlc-tracker`, et application de démonstration « Console SDLC » (dogfooding).

Le framework s'utilise sur lui-même : sa construction est suivie dans `docs/suivi/state.json`
(feature *framework*, 46 tâches, 11 lots), et la Console est l'app qui le met en œuvre.

## 2. Ce qui a fonctionné

- **Specification de référence exhaustive** (`.sdlc/workflow-sdlc.md`, 13 sections) : rôles, principes, 13 étapes, gates, formats de journaux.
- **18 skills homogènes** et portables entre les 3 outils (frontmatter minimal, livrables, critères de fin).
- **Installateur non destructif** (`bin/sdlc-install`) : idempotent, manifeste sha256, `--dry-run`/`--upgrade`/`--uninstall`.
- **CI et contrôles** : `.github/workflows/ci.yml` (syntaxe, complétude, lint config, tests), contrôles de dérive `check_config.py`/`check_completeness.py`.
- **Couverture de tests mesurée** : 28 install + 26 e2e + 87 skills + 81 plugin, tous verts.
- **Dogfooding réel** : la Console SDLC (FastAPI + React + SQLite) et le change `console-sdlc` (70 tâches, 5 specs) archivés.
- **Durcissement final** : tracker rebranché sur `state.json`, baseline migrée dans la skill, `scripts/suivi/` purgé, UI alignée sur la charte, menu « Rapport de clôture ».

## 3. Ce qui a été difficile

- **Dérive de configuration et de suivi** : la config, le suivi et les scripts avaient divergé (clés non documentées, `state.json` désynchronisé de `tasks.md`, copie `scripts/suivi/` obsolète).
- **Section 11 (plugin) restée inachevée** longtemps : source de vérité `state.json`, règle « relecteur ≠ auteur » et baseline non rebranchées avant le durcissement.
- **Deux modèles de suivi** (HTML puis `state.json`) ont coexisté, avec des fixtures et scripts dupliqués.
- **Incohérences mono/multi** (ouverture de phase, sélection visuelle) révélées seulement à l'usage.
- **Git réservé à l'humain** : les agents proposent les commits, ce qui impose des cycles de validation.

## 6. Feedbacks

- Le principe « rien n'est inventé » a été tenu : les métriques non mesurées restent « non mesuré » plutôt qu'estimées.
- Le dogfooding (Console + tracker) a révélé des incohérences que les tests unitaires ne voyaient pas (rendu UI, hooks).
- La séparation orchestrateur / exécutant / relecteur a bien fonctionné ; la contrainte « relecteur ≠ auteur » est désormais appliquée par le tracker.
